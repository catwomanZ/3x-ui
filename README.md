# 3x-ui on Railway — تک‌پورتی

پنل **3x-ui (سنایی)** نسخه `v3.9.0` روی Railway، پشت **یک** پورت HTTPS.

ریلوی به هر سرویس فقط **یک پورت عمومی** می‌دهد و TLS را خودش در لبه‌ی شبکه
انجام می‌دهد. پنل پورت ۲۰۵۳ می‌خواهد، سرویس ساب‌اسکریپشن ۲۰۹۶ و اینباند Xray
پورت خودش را. هر سه روی `127.0.0.1` می‌نشینند و nginx آن‌ها را بر اساس مسیر URL
جدا می‌کند:

```
client ──https──▶ Railway edge (TLS) ──http──▶ nginx :$PORT
                                                 ├─ /<PANEL_PATH>/  → پنل      127.0.0.1:2053
                                                 ├─ /sub            → صفحه‌ی ساب (sidecar پایتون :2097)
                                                 ├─ /sub/<subId>    → ساب      127.0.0.1:2096
                                                 ├─ /ws             → Xray     127.0.0.1:10085
                                                 ├─ /healthz        → 200
                                                 └─ /               → 404
```

## راه‌اندازی روی Railway

1. این چهار فایل را در یک ریپازیتوری GitHub بگذارید.
2. Railway → **New Project** → **Deploy from GitHub repo** → همین ریپو.
3. **Settings → Volumes → Add volume** با Mount Path برابر `/etc/x-ui`
   (بدون این، هر دیپلوی همه‌چیز را پاک می‌کند).
4. **Settings → Networking → Generate Domain**، بعد **Redeploy**.
   `RAILWAY_PUBLIC_DOMAIN` فقط در دیپلوی *بعدی* داخل کانتینر ظاهر می‌شود.
5. لاگ دیپلوی را باز کنید: آدرس پنل، رمز و لینک `vless://` همان‌جا چاپ می‌شود.

## متغیرها (Railway → Variables)

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `ADMIN_USERNAME` | `admin` (فقط بوت اول) | کاربر ورود به پنل |
| `ADMIN_PASSWORD` | `admin` (فقط بوت اول) | اگر در Variables بگذاری، در **هر** بوت اعمال می‌شود و رمز عوض‌شده در پنل را بازنویسی می‌کند |
| `PANEL_PATH` | `/panel/` | مسیر پنل |
| `SUB_PATH` | `/sub/` | مسیر عمومی ساب‌اسکریپشن |
| `CLIENT_SUBID` | `mobile` | لینک ساب می‌شود `https://<domain>/sub/<subId>` |
| `TUNNEL_PATH` | `/ws` | مسیر تونل |
| `TRANSPORT` | `ws` | `ws` در همه‌ی کلاینت‌ها کار می‌کند؛ `xhttp` مقاوم‌تر است ولی پشتیبانی ضعیف‌تر |
| `PUBLIC_HOST` | `RAILWAY_PUBLIC_DOMAIN` | دامنه‌ای که داخل لینک‌ها و `subURI` نوشته می‌شود |
| `PUBLIC_PORT` | `443` | پورت بیرونی که Railway ترافیک HTTP را روی آن می‌آورد |
| `PUBLIC_TLS` | `tls` | لبه‌ی ریلوی TLS را انجام می‌دهد، پس لینک باید `tls` بگوید |
| `BRAND` | `CATWOMAN` | اسم برند روی پنل (عنوان تب، صفحه‌ی ورود، سایدبار) |
| `INBOUND_REMARK` | *(همان `BRAND`)* | اسم ورودی در بخش **ورودی‌ها** و نام هاست در **میزبان‌ها** |
| `REMARK_TEMPLATE` | `CATWOMAN • {{EMAIL}}` | قالب نام کانفیگ در اپ؛ `{{EMAIL}}` همان فیلد هر کلاینت است |
| `SUB_TITLE` | *(همان `BRAND`)* | عنوان بالای صفحه‌ی ساب |
| `SUB_ANNOUNCE` | `این پنل توسط Catwoman ساخته شده` | متن اعلان صفحه‌ی ساب |
| `SUB_SUPPORT_URL` | `t.me/Catwoman_ZaHra` | لینک **فوتر** صفحه‌ی ساب (پایین صفحه) |
| `TZ` | `Asia/Tehran` | منطقه‌ی زمانی کانتینر؛ پنل تاریخ‌ها را با همین نشان می‌دهد |
| `SUBPAGE_PORT` | `2097` | پورت داخلی forwarder جلوی sub server |
| `SUB_PORT` | `2096` | پورت داخلی sub server خودِ 3x-ui (خروجی خام base64) |

## ورود و رمز

پنل در **بوت اول** با `admin` / `admin` بالا می‌آید — هیچ Variable لازم نیست.

بعد از آن رمز را از **Panel Settings** عوض کن؛ عوض می‌ماند. اسکریپت در بوت‌های
بعدی به رمز دست نمی‌زند، چون دیتابیس روی Volume است.

یک استثنا: اگر `ADMIN_USERNAME` و `ADMIN_PASSWORD` را **هر دو** در Railway
Variables بگذاری، در هر بوت اعمال می‌شوند و رمزی که در پنل عوض کرده بودی را
بازنویسی می‌کنند. این راه نجات وقتی است که رمز را گم کرده باشی.

## صفحه‌ی ساب و برندینگ

### صفحه‌ی ساب

صفحه‌ی ساب **همان صفحه‌ی پیش‌فرض خود 3x-ui است** (`internal/web/dist/subpage.html`)،
دست‌نخورده. دو فیلد از تنظیمات خودِ پنل رویش می‌نشیند:

| کلید | برچسب فارسی در پنل | مقدار | کجا دیده می‌شود |
|---|---|---|---|
| `subTitle` | «عنوان اشتراک» | `CATWOMAN` | عنوان بالای کارت |
| `subAnnounce` | «اعلان» | `ساخته شده توسط t.me/Catwoman_ZaHra` | باکس اعلان زیرش |

هر دو با `SUB_TITLE` و `SUB_ANNOUNCE` قابل تغییرند، و مثل بقیه فقط وقتی
نوشته می‌شوند که خالی باشند — متنی که خودت در پنل بنویسی بازنویسی نمی‌شود.

این صفحه یک اپلیکیشن React است که CSS و JS خودش را از
`/<subPath>/assets/...` می‌گیرد — یعنی مسیر تصادفی خودش، **نه** زیر `/sub/`.
بدون یک قاعده‌ی nginx برای آن مسیر، هر ۲۷ فایلش ۴۰۴ می‌شد و صفحه سفید
می‌آمد. آن قاعده اضافه شده و هر ۲۷ فایل ۲۰۰ می‌دهند.

بین `/sub/` و sub server یک forwarder نازک است که **هیچ چیزی رندر نمی‌کند**.
فقط یک کار می‌کند: هدر `Subscription-Userinfo` را وقتی کلاینت سقف ندارد حذف
می‌کند (پایین‌تر توضیح داده شده). بقیه‌ی همه‌چیز — وضعیت، نوع محتوا، بدنه و
بقیه‌ی هدرها مثل `Profile-Title` — دست‌نخورده رد می‌شود.

`/sub` بدون Sub ID به کلاینت پیش‌فرض (`CLIENT_SUBID`) می‌رسد، چون sub server
صفحه‌ی فهرست ندارد و ۴۰۴ می‌داد.

### هدر حجم و چرا v2box «شکست» می‌زد

3x-ui همیشه هدر `Subscription-Userinfo` را می‌فرستد، با صفر برای هر سقفی که
کلاینت ندارد (`internal/sub/calendar_expire.go`):

```
upload=60453; download=102924; total=0; expire=0
```

`total=0` یعنی سقف حجم ندارد. اپ‌هایی مثل v2box مصرف را بر `total` تقسیم
می‌کنند، می‌خورند به صفر، و خطا می‌دهند — در حالی که خودِ کانفیگ‌ها سالم
رسیده‌اند. برای همین هدر فقط وقتی فرستاده می‌شود که چیزی برای گفتن داشته
باشد:

| کلاینت | هدر |
|---|---|
| بدون سقف و بدون انقضا | فرستاده نمی‌شود |
| سقف حجم دارد | `upload=…; download=…; total=…; expire=…` |

**برای اینکه حجم در اپ دیده شود، باید در پنل برای کلاینت سقف حجم بگذاری**
(کلاینت‌ها → ویرایش → کلاینت). تا وقتی سقف نداشته باشد، عددی وجود ندارد که
نشان داده شود.

### تاریخ انقضا و منطقه‌ی زمانی

کانتینرهای Railway با **UTC** بالا می‌آیند، ولی پنل تاریخ‌ها را در منطقه‌ی
زمانیِ خودش نشان می‌دهد. برای کسی که در تهران است، «فردا» سه ساعت و نیم
اختلاف می‌خورد — کافی است کلاینتی که منقضی نیست، منقضی به‌نظر برسد. حالا `TZ`
پیش‌فرض `Asia/Tehran` است (با متغیر `TZ` قابل تغییر).

`expiryTime` در دیتابیس **میلی‌ثانیه** است. اگر به شکل ثانیه ذخیره شود، پنل آن
را ژانویه‌ی ۱۹۷۰ می‌خواند و کلاینت از لحظه‌ی ساخت «منقضی» نشان داده می‌شود.
فرم پنل میلی‌ثانیه می‌فرستد (`.valueOf()`)، پس از این راه نباید اتفاق بیفتد —
ولی اگر بیفتد، در لاگِ بوت یک هشدار صریح چاپ می‌شود که کدام کلاینت و چرا.

### نام کانفیگ‌ها

`remarkTemplate` پیش‌فرض پنل این است:

```
{{INBOUND}}-{{EMAIL}}|📊{{TRAFFIC_LEFT}}|⏳{{DAYS_LEFT}}D
```

اینجا روی `CATWOMAN • {{EMAIL}}` ست می‌شود، پس هر کاربر در اپ اسم خودش را
می‌بیند. `{{EMAIL}}` همان فیلدی است که در پنل موقع ساخت کلاینت پر می‌شود.

`remarkTemplate` هیچ flag در CLI ندارد، پس مستقیم در جدول `settings` نوشته
می‌شود — **قبل از** بالا آمدن پنل. فقط وقتی بازنویسی می‌شود که مقدار فعلی
خالی یا همان پیش‌فرض بالادستی باشد، تا قالبی که دستی تنظیم کرده باشی هر
ری‌استارت نابود نشود.

در لینک، `•` به `%E2%80%A2` encode می‌شود؛ این رفتار استاندارد URI است و اپ
همان `•` را نشان می‌دهد.

## کاربر جدید — ساده‌ترین راه

لازم نیست اینباند بسازی یا لینک تازه بدهی. فقط:

1. پنل → **Clients** → **Add Client**
2. یک **Email** بده (مثلاً `ali`) و در فیلد **Sub ID** دقیقاً `mobile` را بنویس
   (همان `CLIENT_SUBID` پیش‌فرض)
3. ذخیره

تمام. کانفیگ او خودش به همان لینک ساب اضافه می‌شود:

```
https://<دامنه>/sub/mobile
```

هر کسی آن لینک را در v2rayNG / Streisand وارد کند، **همه‌ی** کانفیگ‌هایی که
`subId=mobile` دارند را یک‌جا می‌گیرد. این با تست تأیید شده: با دو کلاینت که
subId مشترک داشتند، `/sub/mobile` هر دو لینک `vless://` را برگرداند.

اگر به یک نفر لینک اختصاصی می‌خواهی، Sub ID متفاوت بده — آن‌وقت لینکش
`https://<دامنه>/sub/<همان subId>` می‌شود. مسیر `/sub/` برای هر subId کار
می‌کند و نیازی به تغییر nginx نیست.

## دو نکته‌ی مهم درباره‌ی خودِ 3x-ui

این دو مورد با تست روی باینری واقعی `v3.9.0` به‌دست آمده، نه از روی مستندات:

1. **مسیر API** برابر `<webBasePath>panel/api/` است. با `PANEL_PATH=/panel/`
   می‌شود `/panel/panel/api/...` که شبیه غلط تایپی است ولی درست است. حدس‌زدن
   `<webBasePath>api/` روی همه‌ی درخواست‌ها ۴۰۴ می‌دهد.
2. **nginx باید URI را دست‌نخورده رد کند.** اگر به `proxy_pass` اسلش اضافه
   کنید پیشوند حذف می‌شود و فایل‌های SPA که آدرس مطلق `/panel/assets/...`
   دارند ۴۰۴ می‌شوند.

## تست‌شده

روی باینری رسمی `x-ui v3.9.0` به‌صورت واقعی اجرا و بررسی شد:

| بررسی | نتیجه |
|---|---|
| `nginx -t` روی کانفیگ رندرشده | syntax ok / test successful |
| `bash -n entrypoint.sh` | بدون خطا |
| `/healthz` | `200 ok` |
| صفحه‌ی ورود پنل + فایل JS آن | `200` / `200` |
| `/sub/mobile` | base64 معتبر، دکد می‌شود به لینک `vless://` |
| هندشیک WebSocket روی `/ws` از طریق nginx | `101 Switching Protocols` |
| `/` برای اسکنرها | `404` |
| اینباند Xray در `bin/config.json` | `vless/ws` روی ۱۰۰۸۵، مسیر `/ws`، کلاینت `user1` |

ساخت ایمیج Docker در محیط تست انجام **نشده** (دمون Docker در دسترس نبود)؛
اسکریپت‌ها بیرون از کانتینر، روی همان باینری رسمی، اجرا و بررسی شدند.
