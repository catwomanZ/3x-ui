# 3x-ui on Railway — تک‌پورتی

پنل **3x-ui (سنایی)** نسخه `v3.9.0` روی Railway، پشت **یک** پورت HTTPS،
با برند `CATWOMAN` و لینک ساب `…/sub/CATWOMAN`.

ریلوی به هر سرویس فقط **یک پورت عمومی** می‌دهد و TLS را خودش در لبه‌ی شبکه
انجام می‌دهد. پنل پورت ۲۰۵۳ می‌خواهد، سرویس ساب‌اسکریپشن ۲۰۹۶ و اینباند Xray
پورت خودش را. هر سه روی `127.0.0.1` می‌نشینند و nginx آن‌ها را بر اساس مسیر URL
جدا می‌کند:

```
client ──https──▶ Railway edge (TLS) ──http──▶ nginx :$PORT
   ├─ /healthz              → 200
   ├─ /<PANEL_PATH>/        → پنل        127.0.0.1:2053   (+ sub_filter برند)
   ├─ = /sub   و  /sub/…    → forwarder  127.0.0.1:2097 ──▶ sub server :2096
   ├─ /<subPath>/…          → sub server 127.0.0.1:2096   (فایل‌های CSS/JS صفحه)
   ├─ /ws                   → Xray       127.0.0.1:10085
   └─ /                     → 404
```

`<subPath>` یک مسیر تصادفی است که خود 3x-ui می‌سازد (مثلاً
`/88exqelotncehi3m/`) و در هر دیتابیس تازه فرق می‌کند؛ اسکریپت موقع بوت از
جدول `settings` می‌خواندش.

## فایل‌ها

| فایل | کار |
|---|---|
| `Dockerfile` | دبیان + باینری رسمی `x-ui v3.9.0` + nginx |
| `entrypoint.sh` | همه‌ی تنظیم‌ها، ساخت اینباند و کلاینت اول، بالا آوردن سه سرویس |
| `nginx.conf.template` | تفکیک مسیرها روی یک پورت + `sub_filter` برند |
| `subserver.py` | forwarder نازک جلوی sub server (پایین توضیح داده شده) |
| `railway.json` | healthcheck و سیاست ری‌استارت |

## راه‌اندازی روی Railway

1. Railway → **New Project** → **Deploy from GitHub repo** → همین ریپو.
2. **Settings → Volumes → Add volume** با Mount Path برابر `/etc/x-ui`.
   بدون این، هر دیپلوی کل دیتابیس — کلاینت‌ها، رمز، تنظیمات — پاک می‌شود.
3. **Settings → Networking → Generate Domain**، بعد حتماً **Redeploy**.
   `RAILWAY_PUBLIC_DOMAIN` فقط در دیپلوی *بعدی* داخل کانتینر ظاهر می‌شود، پس
   بدون آن ری‌دیپلوی لینک‌ها با دامنه‌ی خالی ساخته می‌شوند.
4. لاگ دیپلوی را باز کن: آدرس پنل، نام کاربری و لینک ساب همان‌جا چاپ می‌شود.

## ورود و رمز

پنل در **بوت اول** با `admin` / `admin` بالا می‌آید — هیچ Variable لازم نیست.

بعد از آن رمز را از **پنل ← تنظیمات پنل ← احرازهویت ← اعتبارنامه‌های ادمین**
عوض کن؛ عوض می‌ماند. اسکریپت در بوت‌های بعدی به رمز دست نمی‌زند، چون دیتابیس
روی Volume است.

یک استثنا: اگر `ADMIN_USERNAME` و `ADMIN_PASSWORD` را **هر دو** در Railway
Variables بگذاری، در هر بوت اعمال می‌شوند و رمزی که در پنل عوض کرده بودی را
بازنویسی می‌کنند. این راه نجات وقتی است که رمز را گم کرده باشی — بگذار،
Redeploy کن، وارد شو، پاکشان کن، دوباره Redeploy.

## کاربر جدید — ساده‌ترین راه

لازم نیست اینباند بسازی یا لینک تازه بدهی. فقط:

1. پنل ← **Clients** ← **Add Client**
2. یک **Email** بده (مثلاً `ali`) و در فیلد **Sub ID** دقیقاً `CATWOMAN` را بنویس
3. در قسمت اینباند، **تیک ورودی `CATWOMAN` را بزن**
4. ذخیره

تمام. کانفیگ او خودش به همان لینک اضافه می‌شود:

```
https://<دامنه>/sub/CATWOMAN
```

هر کسی آن لینک را در v2rayNG / Streisand وارد کند، **همه‌ی** کانفیگ‌هایی که
`subId=CATWOMAN` دارند را یک‌جا می‌گیرد. با تست تأیید شده: با دو کلاینت که
subId مشترک داشتند، `/sub/CATWOMAN` هر دو لینک `vless://` را برگرداند.

اگر به یک نفر لینک اختصاصی می‌خواهی، Sub ID متفاوت بده — آن‌وقت لینکش
`https://<دامنه>/sub/<همان subId>` می‌شود. نیازی به تغییر nginx نیست.

دو نکته که با تست روی باینری واقعی به‌دست آمده:

- **حروف بزرگ و کوچک مهم است.** `/sub/CATWOMAN` کار می‌کند، `/sub/catwoman`
  می‌شود `404`.
- **بدون تیک اینباند، کلاینت ساخته نمی‌شود.** پنل رد می‌کند با
  `Something went wrong (at least one inbound is required)`.

### چه اسمی می‌شود گذاشت

3x-ui کاراکترهای زیر را در Email کلاینت رد می‌کند
(`internal/web/service/client_crud.go` → `hasForbiddenClientChar`):

`/` ، `\` ، هر کاراکتر کنترلی، و **هر نوع فاصله** — شامل فاصله‌ی معمولی و
نیم‌فاصله.

| اسم | نتیجه |
|---|---|
| `myfriend` | ✅ قبول |
| `علیرضا` | ✅ قبول |
| `اسم‌دلخواه‌من` | ✅ قبول (نیم‌فاصله داخلش ایرادی ندارد) |
| `Ali Reza` | ❌ `client email contains an invalid character` |

## صفحه‌ی ساب

### صفحه‌ی خودِ 3x-ui، دست‌نخورده

صفحه‌ی ساب **همان صفحه‌ی پیش‌فرض خود 3x-ui است**
(`internal/web/dist/subpage.html`). هیچ HTML جداگانه‌ای ساخته نمی‌شود. سه فیلد
از تنظیمات خودِ پنل رویش می‌نشیند:

| کلید | برچسب فارسی در پنل | مقدار پیش‌فرض | کجا دیده می‌شود |
|---|---|---|---|
| `subTitle` | «عنوان اشتراک» | `CATWOMAN` | عنوان بالای کارت |
| `subAnnounce` | «اعلان» | `این پنل توسط Catwoman ساخته شده` | باکس اعلان |
| `subSupportUrl` | «پشتیبانی» | `t.me/Catwoman_ZaHra` | **فوتر، پایین صفحه** |

`subSupportUrl` داخل `<footer class="sub-footer">` رندر می‌شود، و 3x-ui با
`EnsureURLScheme` خودش `https://` را اضافه می‌کند — پس لینک کلیک‌خور است.

هر سه با `SUB_TITLE` / `SUB_ANNOUNCE` / `SUB_SUPPORT_URL` قابل تغییرند و
**فقط وقتی نوشته می‌شوند که خالی باشند**. متنی که خودت در پنل بنویسی در هر
ری‌استارت بازنویسی نمی‌شود.

### مرورگر صفحه می‌بیند، اپ کانفیگ

همان آدرس، دو رفتار. تصمیم را خود 3x-ui می‌گیرد (`maybeServeSubPage`): اگر
`Accept` شامل `text/html` باشد صفحه را می‌دهد، وگرنه خروجی خام base64.

مشکل این بود که خیلی از اپ‌ها `Accept` مبهم می‌فرستند (`*/*` یا اصلاً هیچی)،
پس در کروم گوشی هم صفحه نمی‌آمد. forwarder جلوی sub server فقط در یک حالت
دست به کار می‌شود: `Accept` مبهم یا خالی باشد **و** User-Agent آشکارا مرورگر
باشد. آن‌وقت `Accept` را به `text/html,…` عوض می‌کند.

اگر `Accept` از قبل یک نوع مشخص غیر HTML گفته باشد (مثل `application/json`
که Alamofire می‌فرستد) هیچ چیز عوض نمی‌شود.

فهرست مرورگرها عمداً `android` / `iphone` / `ipad` **ندارد**: User-Agent اپ‌ها
معمولاً نام پلتفرم را دارد
(`Streisand/1.6.43 (com.kavakebi.streisand; build 1; iOS 17.5.1) Alamofire/5.10.2`)
و تطبیق روی نام پلتفرم، به جای کانفیگ، صفحه‌ی HTML به اپ می‌داد.

`/sub` بدون Sub ID به کلاینت پیش‌فرض (`CLIENT_SUBID`) می‌رسد، چون sub server
صفحه‌ی فهرست ندارد و ۴۰۴ می‌داد.

### چرا فایل‌های CSS/JS مسیر جدا می‌خواهند

این صفحه یک اپلیکیشن React است که دارایی‌هایش را از `/<subPath>/assets/…`
می‌گیرد — یعنی از آن مسیر تصادفی، **نه** از زیر `/sub/`. بدون یک قاعده‌ی nginx
برای آن مسیر، هر ۲۷ فایلش ۴۰۴ می‌شد و صفحه سفید می‌آمد، در حالی که `curl` روی
خود صفحه `200` می‌داد. آن قاعده اضافه شده و هر ۲۷ فایل `200` می‌دهند.

### هدر حجم، و چرا v2box «شکست» می‌زد

3x-ui همیشه هدر `Subscription-Userinfo` را می‌فرستد، با صفر برای هر سقفی که
کلاینت ندارد (`internal/sub/calendar_expire.go:10-21` — هیچ شرطی در کار نیست):

```
upload=60453; download=102924; total=0; expire=0
```

`total=0` یعنی سقف حجم ندارد. اپ‌هایی مثل v2box مصرف را بر `total` تقسیم
می‌کنند، به صفر می‌خورند و خطا می‌دهند — در حالی که خودِ کانفیگ‌ها سالم
رسیده‌اند. برای همین هدر فقط وقتی فرستاده می‌شود که چیزی برای گفتن داشته
باشد (`total>0` یا `expire>0`)؛ `Profile-Update-Interval` همیشه می‌ماند.

**برای اینکه حجم در اپ دیده شود، باید در پنل برای کلاینت سقف حجم بگذاری**
(کلاینت‌ها ← ویرایش ← کلاینت). تا وقتی سقف نداشته باشد، عددی وجود ندارد که
نشان داده شود.

## تاریخ انقضا

کانتینرهای Railway با **UTC** بالا می‌آیند، ولی پنل تاریخ‌ها را در منطقه‌ی
زمانیِ خودش نشان می‌دهد. برای کسی که در تهران است، «فردا» سه ساعت و نیم
اختلاف می‌خورد — کافی است کلاینتی که منقضی نیست، منقضی به‌نظر برسد. حالا `TZ`
پیش‌فرض `Asia/Tehran` است.

`expiryTime` در دیتابیس **میلی‌ثانیه** است. اگر به شکل ثانیه ذخیره شود، پنل
آن را ژانویه‌ی ۱۹۷۰ می‌خواند و کلاینت از لحظه‌ی ساخت «منقضی» نشان داده
می‌شود. فرم پنل میلی‌ثانیه می‌فرستد (`.valueOf()`)، پس از این راه نباید اتفاق
بیفتد — ولی اگر بیفتد، در لاگِ بوت یک هشدار صریح چاپ می‌شود که کدام کلاینت و
چرا.

منطق خودِ صفحه‌ی ساب: `expire>0 && now>=expire` → «منقضی»؛ `expire<=0` →
«نامحدود». پس مقدار منفی (مسیر «شروع با تأخیر» در فرم) قرمز نمی‌شود، آبی
می‌شود.

## برند

### داخل پنل

پنل 3x-ui فرانت‌اند را با `//go:embed all:dist` داخل باینری می‌کشد
(`internal/web/web.go:56`) و فقط وقتی `XUI_DEBUG=true` باشد از روی دیسک
می‌خواند — یعنی **نمی‌شود فایل‌هایش را روی دیسک عوض کرد**. پس برند با
`sub_filter` در nginx اعمال می‌شود:

- `<title>` صفحه‌ی ورود
- `brand-name` در صفحه‌ی ورود
- `drawer-brand` در سایدبار
- `remark` اینباند و `remark` هاست‌ها در `streamSettings.externalProxy`

دست‌نخورده باقی می‌ماند: `3X-UI Version`، متن «به‌روزرسانی خود 3X-UI»، و همه‌ی
نام کلاس‌های CSS. برای همین **فونت و چیدمان عوض نمی‌شود**.

`sub_filter` به `proxy_set_header Accept-Encoding "";` نیاز دارد وگرنه nginx
پاسخ فشرده را نمی‌بیند، و `sub_filter_types` فقط نوع‌های JS را می‌گیرد —
`text/html` را نمی‌شود نوشت چون `duplicate MIME type` می‌دهد.

### نام کانفیگ‌ها

`remarkTemplate` پیش‌فرض پنل این است:

```
{{INBOUND}}-{{EMAIL}}|📊{{TRAFFIC_LEFT}}|⏳{{DAYS_LEFT}}D
```

اینجا روی `CATWOMAN • {{EMAIL}}` ست می‌شود، پس هر کاربر در اپ اسم خودش را
می‌بیند. `{{EMAIL}}` همان فیلدی است که موقع ساخت کلاینت پر می‌شود. توکن‌های
دیگر: `{{ID}}` `{{SHORT_ID}}` `{{SUB_ID}}` `{{TELEGRAM_ID}}`.

`remarkTemplate` هیچ flag در CLI ندارد، پس مستقیم در جدول `settings` نوشته
می‌شود — **قبل از** بالا آمدن پنل. فقط وقتی بازنویسی می‌شود که مقدار فعلی
خالی یا همان پیش‌فرض بالادستی باشد، تا قالبی که دستی تنظیم کرده باشی هر
ری‌استارت نابود نشود.

در لینک، `•` به `%E2%80%A2` encode می‌شود؛ این رفتار استاندارد URI است و اپ
همان `•` را نشان می‌دهد.

## مهاجرت‌های خودکار

اسکریپت در هر بوت، قبل از خواندن پنل، دو چیز را سرِ جای خود می‌گذارد:

**۱. نام قدیمی ورودی.** مقدار پیش‌فرض قبلی `railway` بود. هر ورودی یا هاستی
که `remark`-اش **دقیقاً** `railway` باشد به `CATWOMAN` تبدیل می‌شود — هم در
جدول `inbounds` و هم داخل `streamSettings.externalProxy`. اسمی که خودت گذاشته
باشی دست نمی‌خورد.

**۲. `subId` قدیمی.** `CLIENT_SUBID` قبلاً `mobile` بود. چون `sub_id` روی هر
کلاینت جداگانه ذخیره می‌شود، عوض کردن پیش‌فرض به‌تنهایی کلاینت‌های موجود را
بی‌صاحب می‌کرد: لینک دست بقیه `CATWOMAN` می‌شد ولی کلاینت هنوز `mobile` داشت،
یعنی صفحه‌ی خالی. پس کلاینت‌هایی که `sub_id`-شان **دقیقاً** `mobile` است
منتقل می‌شوند و در لاگ نوشته می‌شود:

```
[entrypoint] moved 1 client(s) from subId 'mobile' to 'CATWOMAN': user1.
The subscription link is now /sub/CATWOMAN; the old /sub/mobile no longer
resolves, so re-add the link on any phone still using it.
```

**نتیجه:** لینک `/sub/mobile` دیگر کار نمی‌کند. روی هر گوشی که هنوز آن را
دارد، لینک جدید را جایگزین کن. هر دو مهاجرت تکرارپذیرند — بوت دوم هیچ
پیامی نمی‌دهد.

## نکته‌های 3x-ui که با تست به‌دست آمده

اینها روی باینری واقعی `v3.9.0` بررسی شده، نه از روی مستندات:

1. **مسیر API** برابر `<webBasePath>panel/api/` است. با `PANEL_PATH=/panel/`
   می‌شود `/panel/panel/api/...` که شبیه غلط تایپی است ولی درست است. حدس‌زدن
   `<webBasePath>api/` روی همه‌ی درخواست‌ها ۴۰۴ می‌دهد. ورود هم به CSRF token
   نیاز دارد (`GET <base>panel/csrf-token`).
2. **nginx باید URI را دست‌نخورده رد کند.** اگر به `proxy_pass` اسلش اضافه
   کنید پیشوند حذف می‌شود و فایل‌های SPA که آدرس مطلق `/panel/assets/...`
   دارند ۴۰۴ می‌شوند.
3. **پنل `settings` را در حافظه کش می‌کند.** دستکاری مستقیم دیتابیس، صفحه‌ی
   در حال سرو را عوض نمی‌کند؛ پنل باید ری‌استارت شود.
4. **ساخت/ویرایش اینباند `bin/config.json` را مطمئن بازتولید نمی‌کند**، پس
   اسکریپت بعد از بوت‌استرپ یک بار پنل را ری‌استارت می‌کند.
5. **جدول `client_traffics` جداست.** کلاینتی که ردیفی آنجا ندارد برای sub
   server نامرئی است.
6. **`subPath` در هر دیتابیس تازه عوض می‌شود** و به `/` ختم می‌شود.
